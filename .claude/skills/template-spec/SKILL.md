# 템플릿 기획 명세

트렌드 신호 하나를 **판매 가능한 템플릿 기획서**로 바꾼다.
이 명세서가 있어야 "예쁜 그림 뽑기"가 아니라 "바로 쓰는 템플릿 세트"를 만들 수 있다.

산출물: `templates/specs/<주제>-<날짜>.md` (양식은 `assets/spec-template.md`)

## 이 스킬이 푸는 문제

양산공장은 "컷 한 장"을 만든다. 하지만 템플릿 판매자는 **"바로 쓰는 세트"**에서 효용을 느낀다.
그 사이에 빠진 것이 **기획 명세** — "이 트렌드를 잡으려면 어떤 부품이 몇 개 필요한가"를
사람이 정하는 단계다. 이걸 양식으로 고정해두면 매번 같은 깊이로 기획할 수 있다.

## 세 가지 핵심 원칙 (지피티 검토)

1. **승인 ≠ 수익.** "최근 승인된 결"과 "오래 노출되는 결(스테디)"을 분리해서 본다.
   둘 다에 나타나는 요소가 "지금 만들어도 오래 갈 뼈대". trends.csv의 `스테디플래그`가 근거.

2. **베끼지 않는다.** 승인작은 결(방향)만 참고. 레이아웃·에셋·문구는 독자 제작.
   명세서 §8에 레퍼런스별로 "따라하면 안 되는 고유 요소 / 참고 가능한 원칙"을 분리 기록한다.

3. **낱장보다 가족.** 한 주제 = 카드뉴스 + 포스터 + 배너 + SNS 정사각을 같은 디자인 언어로 묶은 세트.
   명세서 §5가 이 가족을 정의한다.

## 워크플로

### 1. 주제 선정 근거 확인
`templates/trends.csv`와 최신 `templates/reports/trend-*.md`를 읽는다.
사용자가 주제를 지정했으면 그 주제의 근거를(검색순위·스테디·최근승인) CSV에서 찾아 뒷받침한다.
지정하지 않았으면 리포트에서 유망 후보 2~3개를 제시하고 사용자가 고르게 한다.

근거로 삼을 신호:
- **스테디셀러 후보** = 오래 가는 뼈대 (시즌 무관 정보구조·용도)
- **최근 14일 승인 신작** = 지금 통과되는 색·여백·구성
- 둘이 겹치는 지점 = 가장 안전한 기획

### 2. 레이아웃 눈으로 분해 (사람 몫)
CSV·리포트는 "무엇이 있나"까지만 안다. **"사용자가 무엇을 쉽게 바꾸나"**는 사람이 미캔에서
실제 템플릿을 열어 눈으로 봐야 한다. 사진 슬롯 수, 가격 배지, 페이지 구성, 제목 위치 —
이걸 사용자에게 물어 명세서 §3·§4를 채운다. 모르면 비워두고 "여기는 미캔에서 확인 필요"로 표시.

### 3. 명세서 작성
`assets/spec-template.md`를 복사해 `templates/specs/<주제>-<날짜>.md`로 채운다.
`{{...}}` 자리를 전부 실제 값으로. 8개 섹션:
1. 기회 요약 (수요 신호·시즌·바구니)
2. 다섯 가지 기록 (용도/타깃/제목영역/정보량/색·분위기)
3. 레이아웃 패턴 (바꾸는 것 / 고정하는 것)
4. 기능 포인트 (편집 지점)
5. 템플릿 가족 (형태별 세트)
6. 필요 생산물 (부품 주문서)
7. 시리즈화 (색×업종×비율)
8. 표절 방지 메모

### 4. 부품 주문서 → stock-batch로 연결
명세서 §6의 "필요 생산물" 표가 곧 배치 주문서다. 각 행이 `stock-batch` 스펙 하나가 된다.
사용자가 "이제 부품 만들어" 하면 `stock-batch` 스킬로 넘어가 §6 항목을 배치로 생성한다.

## 3바구니 기획 (매주 균형)

주제를 고를 때 한쪽에 쏠리지 않게 세 바구니로 나눈다 (지피티 권고):

| 바구니 | 비중 | 예 |
|---|---|---|
| **시즌 선점** | 40% | 명절·입학·행사 등 4~8주 앞. 지금이 8월이면 추석·가을 |
| **상시 수요** | 40% | 모집·할인·메뉴·공지·후기·예약 — 계절 안 타는 것 |
| **틈새 실험** | 20% | 최근 승인작에서 보인 새 분위기 |

트렌드만 쫓으면 시즌 끝나고 재고가 죽는다. 상시 수요가 바닥을 받쳐준다.

## 기회 카드 (여러 승인작 묶어 한 장으로)

사용자가 승인작 묶음을 주면, 명세서 앞에 "기회 카드"를 만들 수 있다:
수요 키워드 / 최근 색·레이아웃 공통점 / 스테디 공통점 / 피해야 할 과밀 요소 /
새로 만들 템플릿 가족 5종. 이건 명세서 §1~§2의 압축판이다.

## 하지 않는 것

- 분석기 썸네일을 재사용하거나 그대로 따라 만들지 않는다.
- 색·무드를 trends.csv의 자동 태그로 판단하지 않는다 (부정확). 사람이 실제로 보고 적는다.

## 사용자에게 보고할 때

이 저장소 사용자는 개발 전문가가 아니다 (`CLAUDE.md` 소통 규칙).
명세서를 다 채우려 하지 말고, **사람이 눈으로 봐야 하는 칸(레이아웃·기능)은 질문으로** 남긴다.
"이 명세서로 부품 몇 개를 만들면 되는지"를 마지막에 한 줄로 요약해준다.
