# 트렌드 인입기

미캔 템플릿 분석기 JSON을 받아 두 가지를 만든다.

| 산출물 | 위치 | 무엇 |
|---|---|---|
| 원본 JSON 보관 | `templates/imports/micans_templates_YYYY-MM-DD.json` | 감사·재계산용 |
| 병합 CSV | `templates/trends.csv` | 컷·검색어별 신호 누적 (append-only) |
| 마크다운 리포트 | `templates/reports/trend-YYYY-MM-DD.md` | 사람이 훑는 요약 |

## 왜 이 스킬이 필요한가

분석기 JSON은 브라우저 로컬에 쌓이고, 사용자가 손으로 "이번 주 뭐 떴지"를 훑어야 한다.
그 훑기를 CSV로 정본화해두면 (1) 매주 같은 방식으로 신호를 비교할 수 있고,
(2) 뒷단 스킬(`template-spec`)이 CSV 위에서 자동으로 초안을 만든다.

## 신뢰하는 신호 · 버리는 신호

분석기가 뽑는 값이 다 같은 품질이 아니다. 이 스킬은 **신뢰 가능한 것만** 뽑는다.

**신뢰 (CSV에 반영)**
- 승인일 (썸네일 URL 날짜 = 실제 승인일에 가까운 근사)
- 검색 키워드별 순위 (구매의도의 대리 신호)
- 페이지 수 (템플릿의 규모·기능 힌트)
- 프리미엄 여부 (유료 판정)
- 카테고리 (첫 세그먼트만)

**버림 (CSV에 안 넣음)**
- 도구가 자동 태깅한 "색상/무드" — 제목 첫·둘째 단어를 쓴 근사치라 부정확
  (매뉴얼과 ChatGPT 리뷰 모두 확인)
- 판매량·수익 — 도구가 못 잡음 (외부 데이터로 나중에 붙일 것)

## 스테디셀러 자동 판정

CSV 인입 시점에 컷마다 계산해 `스테디플래그` 컬럼에 O/X로 붙인다.

기준: **승인 30일 이상 지났는데 검색 순위 20위 이내**.
> "오래됐는데 아직 앞줄"이면 지속적으로 팔린다는 신호. 다음 배치의 중심축 후보다.

기준값(`STEADY_MIN_DAYS`, `STEADY_MAX_RANK`)은 `scripts/intake.py` 상단에 상수로 있다.
데이터가 쌓여 감이 잡히면 조정한다.

## 워크플로 (사용자가 시켰을 때)

1. **JSON 경로 확인** — 사용자가 업로드한 파일이나 로컬 경로
2. **인입 실행**:
   ```bash
   python3 .claude/skills/trend-intake/scripts/intake.py <json_path>
   ```
   같은 수집일·같은 템플릿·같은 검색어 조합은 자동으로 건너뛴다 (중복 방지)
3. **리포트 생성**:
   ```bash
   python3 .claude/skills/trend-intake/scripts/report.py
   ```
4. **사용자에게 보고** — 총 몇 행 · 스테디 몇 개 · 신작 몇 개 · 리포트 경로

## 시험 (실제 JSON 없을 때)

`assets/sample.json`에 형식 그대로의 소량 샘플이 있다.
스크립트가 도는지 확인할 때 이걸로 dry-run 해본다:
```bash
python3 scripts/intake.py assets/sample.json --dry-run
```

## 자주 만날 케이스

- **kwr 비어 있음**: 카테고리 브라우징으로만 잡힌 컷. 순위/키워드 없이 한 행만 생성.
  다음 인입 때 검색으로 다시 잡히면 그때 순위 데이터가 붙는다.
- **같은 컷 여러 키워드 등장**: 컷 하나에 행 여러 개 (키워드마다 한 행).
  이게 정상이고 원하는 모양이다 — 키워드별 순위를 따로 봐야 트렌드가 보인다.
- **같은 파일 두 번 넣기**: 자동으로 중복 건너뜀. 손해 없음.

## 하지 않는 것

- 분석기가 저장한 썸네일 원본을 **다운로드하거나 복제하지 않는다**.
  이 스킬은 메타데이터 병합만 한다. 이미지 저장은 매뉴얼의 안전 규칙(참고용, 복제 금지)을 따른다.
- 색상/무드 자동 판정을 하지 않는다. 그건 나중에 실제 비전 분석으로 별도 스킬을 만들 것.

## 사용자에게 보고할 때
