# 트렌드 인입기

미캔 템플릿 분석기 JSON을 받아 두 가지를 만든다.

| 산출물 | 위치 | 무엇 |
|---|---|---|
| 원본 JSON 보관 | `templates/imports/micans_templates_YYYY-MM-DD.json` | 감사·재계산용 |
| 병합 CSV | `templates/trends.csv` | 컷·검색어별 신호 누적 (append-only) |
| 마크다운 리포트 | `templates/reports/trend-YYYY-MM-DD.md` | 사람이 훑는 요약 |

## 왜 이 스킬이 필요한가

분석기 JSON은 브라우저 로컬에 쌓이고, 사용자가 손으로 "이번 주 뭐 떴지"를 훑어야 한다.
그 훑기를 CSV로 정본화해두면 (1) 매주 같은 방식으로 신호를 비교할 수 있고,
(2) 뒷단 스킬(`template-spec`)이 CSV 위에서 자동으로 초안을 만든다.

## 신뢰하는 신호 · 조심할 신호 · 버리는 신호

분석기가 뽑는 값이 다 같은 품질이 아니다. GPT 검토를 반영해 **표기를 정직하게** 맞춘다.

**신뢰 (CSV에 반영)**
- 페이지 수 (템플릿의 규모·기능 힌트)
- 프리미엄 여부 (유료 판정)
- 카테고리 (첫 세그먼트만)

**조심 — 반영하되 이름으로 한계를 못박음**
- `썸네일날짜` — 썸네일 URL의 날짜. **코드상 '승인일'로 검증된 값이 아니다.**
  그래서 컬럼명도 '승인일'이 아니라 `썸네일날짜`, 리포트에서도 '날짜 신호'로만 부른다.
- `순위` — 그 화면에서 **처음 발견된 순서**. 세션마다 달라질 수 있는 노출 순서지
  확정 인기순위가 아니다. 그래서 `수집일`(관찰 시각)과 항상 함께 저장한다.

**버림 (CSV에 안 넣음)**
- 도구가 자동 태깅한 "색상/무드" — 제목 첫·둘째 단어를 쓴 근사치라 부정확
  (매뉴얼·GPT 모두 지적). 색·무드는 **사람이 실제로 보고** 명세서에 적는다.
- 판매량·수익 — 도구가 못 잡음 (외부 데이터로 나중에 붙일 것)

## RAW 보존 · 파생 분리 (재계산 가능성)

판정 규칙은 언젠가 바뀐다. 그때 옛 데이터를 다시 계산할 수 있어야 한다 (GPT 지적).
그래서 CSV 컬럼을 두 갈래로 못박는다:

- **RAW** (`수집일`·`썸네일날짜`·`순위`·`검색키워드`·`페이지수`·`프리미엄` 등) —
  분석기가 준 값 그대로. **절대 덮어쓰지 않는다.**
- **파생** (`노출후보플래그`·`신호라벨`·`신뢰도`·`판정규칙버전`) —
  RAW 에서 `derive()` 함수 하나로만 계산. 규칙이 바뀌면 RAW 로부터 다시 돌리면 된다.

3중 안전망:
1. 원본 JSON 전체는 `templates/imports/` 에 무손실 보존 (최종 재계산 근거)
2. CSV 의 RAW 컬럼은 파생과 섞이지 않음
3. `판정규칙버전` 컬럼으로 어떤 규칙으로 계산됐는지 행마다 표시

규칙을 바꿔 재계산할 때는 `scripts/recompute.py` 를 쓴다 (RAW 는 그대로, 파생만 새로 씀).

## 검색 노출 기반 후보 자동 판정

CSV 인입 시점에 컷마다 계산해 `노출후보플래그` 컬럼에 O/X로 붙인다.

기준: **썸네일날짜 30일 이상 지났는데 검색 순위 20위 이내**.
> "날짜 신호가 오래됐는데 아직 앞줄"이면 검색에 오래·앞줄 노출된다는 신호.
> **판매·수익이 증명된 게 아니다** — '스테디셀러'라 단정하지 않고 '노출 기반 후보'로만 부른다 (GPT 지적).

기준값(`EXPOSURE_MIN_DAYS`, `EXPOSURE_MAX_RANK`, `RULE_VERSION`)은 `scripts/intake.py` 상단에 상수로 있다.
데이터가 쌓여 감이 잡히면 조정하고, 바꿀 때 `RULE_VERSION`을 올린다.

## 신호 라벨 · 신뢰도

파생 컬럼 `신호라벨`은 행이 어떤 신호인지 사람 언어로 표시한다:
- `노출기반후보` — 날짜 오래 + 앞줄 노출 (판매 아님)
- `노출관측` — 검색에서 순위와 함께 관측됨
- `목록관측` — 카테고리 브라우징으로만 봄 (키워드/순위 없음)

`신뢰도`(높음/중간/낮음)는 근거가 많을수록 높다. 키워드+순위+여러 세션 관측이면 높음,
키워드+순위만 있으면 중간, 목록 관측뿐이면 낮음.

## 워크플로 (사용자가 시켰을 때)

1. **JSON 경로 확인** — 사용자가 업로드한 파일이나 로컬 경로
2. **인입 실행**:
   ```bash
   python3 .claude/skills/trend-intake/scripts/intake.py <json_path>
   ```
   같은 수집일·같은 템플릿·같은 검색어 조합은 자동으로 건너뛴다 (중복 방지)
3. **리포트 생성**:
   ```bash
   python3 .claude/skills/trend-intake/scripts/report.py
   ```
4. **사용자에게 보고** — 총 몇 행 · 스테디 몇 개 · 신작 몇 개 · 리포트 경로

## 시험 (실제 JSON 없을 때)

`assets/sample.json`에 형식 그대로의 소량 샘플이 있다.
스크립트가 도는지 확인할 때 이걸로 dry-run 해본다:
```bash
python3 scripts/intake.py assets/sample.json --dry-run
```

## 자주 만날 케이스

- **kwr 비어 있음**: 카테고리 브라우징으로만 잡힌 컷. 순위/키워드 없이 한 행만 생성.
  다음 인입 때 검색으로 다시 잡히면 그때 순위 데이터가 붙는다.
- **같은 컷 여러 키워드 등장**: 컷 하나에 행 여러 개 (키워드마다 한 행).
  이게 정상이고 원하는 모양이다 — 키워드별 순위를 따로 봐야 트렌드가 보인다.
- **같은 파일 두 번 넣기**: 자동으로 중복 건너뜀. 손해 없음.

## 하지 않는 것

- 분석기가 저장한 썸네일 원본을 **다운로드하거나 복제하지 않는다**.
  이 스킬은 메타데이터 병합만 한다. 이미지 저장은 매뉴얼의 안전 규칙(참고용, 복제 금지)을 따른다.
- 색상/무드 자동 판정을 하지 않는다. 그건 나중에 실제 비전 분석으로 별도 스킬을 만들 것.

## 사용자에게 보고할 때

이 저장소 사용자는 개발 전문가가 아니다 (`CLAUDE.md` 소통 규칙).
경로를 나열하지 말고 **뭐가 몇 개 나왔고 다음에 뭘 보면 되는지**를 한 단계씩 알려준다.
리포트 파일은 위치를 알려주되, 링크가 아니라 "어느 폴더의 어느 파일" 형식으로.
