# 📈 시그널 로그 — 신호→스톡 수익 루프의 데이터 기반

> **원칙: 감이 아니라 판매 신호로 다음 배치를 정한다.**
> 이미지를 많이 뽑아 파는 게 아니라, 팔린 신호를 읽고 필요한 소재만 생산한다.

## 루프 (전 배치 공통)

```
수요 가설 → 1~3장 시안 테스트 → 승인 → 20컷 앵글 분산 → 메타데이터 → 제출
    ↑                                                            ↓
    └────────── signals.csv 성과 기록 (30일/90일) ←──────────────┘
```

- **시안 게이트**: 새 주제는 처음부터 20~40컷 뽑지 않는다. 주제당 1~3장 먼저 생성해
  스타일 승인 후 양산 (앱의 슬롯 수 3장 설정 = 시안 모드).
- **앵글 분산**: 승인된 스타일은 4축 변주(주제×카메라앵글×배경톤×팔레트)로 20컷 내외 확장.
- **형태 4종**: 모든 컷은 `배경형`(여백·카피 배치용) / `제품형`(제품 자리) /
  `인물형`(감정·라이프스타일) / `설명형`(과학·웰니스·테크 콘셉트) 중 하나로 라벨링.

## signals.csv 기록 규칙

| 컬럼 | 기록 시점 | 내용 |
|---|---|---|
| 배치~플랫폼 | 배치 생성 시 | 프롬프트 파일에서 자동 생성 (컷라벨은 파일명·메타데이터와 1:1) |
| 제출일 | 제출 시 | YYYY-MM-DD |
| 어도비승인 / 미캔승인 | 심사 결과 도착 시 | O / X (플랫폼 미제출은 공란) |
| 어도비거절사유 | 거절 시 | 노이즈 / 소프트포커스 / 노출 / 아티팩트 / 유사성 / 기타 |
| DL30 / DL90 | 제출 +30일 / +90일 | 다운로드(판매) 수 |
| 비고 | 수시 | 수동 승격, 라벨 변경 등 |

- 승인/DL 숫자는 **컷 단위**로 기록한다. 배치 합계는 컷에서 집계하면 되지만 역은 불가능.
- 30/90일 체크는 코덱스 대결 성과 비교 일정과 동일 — 한 번 기록으로 두 용도.

## 재투입 (다음 배치 반영)

90일 데이터가 쌓이면 배치 기획 전에 확인:

1. **DL 상위 조합** — 주제축×색축×형태 교차로 무엇이 팔렸나 → 다음 배치의 중심축
2. **승인율** — 어도비 거절사유 반복 패턴 → `DARK_GLOW_RE`/QC 규칙 업데이트 (SKILL.md 라우팅 규칙 참조)
3. **플랫폼 격차** — 미캔에서만 팔리는 유형은 미캔전용 배치로 분리 확대
4. **제로 신호** — 90일 DL 0인 조합은 다음 배치에서 제외 (예쁘다고 다시 만들지 않는다)
